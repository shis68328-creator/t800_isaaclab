## 一、仿真和机器人

### MuJoCo
一个物理仿真引擎。你给它一个机器人模型和一堆关节力矩，它负责算“下一秒机器人会倒还是站稳”。

可以理解成：**机器人版的物理课实验台**。

### Isaac Sim
NVIDIA 的机器人仿真器，基于 Omniverse。它比 MuJoCo 更重，但能利用 GPU 并行跑几千个机器人，适合强化学习。

### Isaac Lab
建立在 Isaac Sim 上的“机器人训练框架”。它把仿真组织成强化学习环境：观测、动作、奖励、终止条件都拆成配置。

一句话：

```text
MuJoCo = 物理实验台
Isaac Sim = 更大型的物理实验台
Isaac Lab = 在实验台上自动安排训练课程
```

### USD
Universal Scene Description，NVIDIA 的场景文件格式。Isaac Sim 不能直接读 MuJoCo 的 MJCF 或 URDF，要先转成 `.usd`。

可以理解成：**Isaac Sim 只吃 USD 这种“文件格式”**。

### MJCF / URDF
两种描述机器人模型的 XML 格式。

- MJCF：MuJoCo 的格式
- URDF：ROS 常用的格式

里面写了：有哪些连杆（link）、关节（joint）、质量、碰撞形状、网格文件。

### Articulation（关节体）
“一根一根连杆用关节连起来”的机器人。T800 就是一个 Articulation。

### DoF（自由度）
机器人能独立运动的维度。T800：

- 25 个驱动关节
- 1 个浮动基座（能在空间里平移 + 旋转）
- 所以 `nq=32`、`nv=31`

### PD 控制
一种最常用的关节控制方法：

```text
力矩 = kp × (目标角度 - 当前角度) - kd × 当前角速度
```

- `kp`：位置增益，越大越“硬”，越用力回到目标角
- `kd`：阻尼，越大越“黏”，越能抑制晃动

类比：**kp 是弹簧，kd 是减震器**。

### 接触传感器（Contact Sensor）
测量“脚有没有踩到地面、踩了多大的力”。`feet_air_time` 这种奖励就靠它。

### 浮动基座
机器人的“身体”没有被钉在地上，可以自由移动。人形机器人都是浮动基座。

## 二、强化学习

### 强化学习（RL）
让机器人自己试错：做动作 → 看奖励 → 调整策略。就像训练小狗：做对了给零食，做错了没零食。

### 策略（Policy）
一个神经网络，输入“当前看到的状态”，输出“接下来做什么动作”。

数学写法：`π(a|s)`，意思是“在状态 s 下选动作 a 的概率”。

### 观测（Observation）
策略能看到的数字。T800 的观测包括：

- 身体速度
- 身体朝向
- 关节角、关节速度
- 上一步动作
- 目标速度指令

**观测里没有的信息，策略就不可能知道。**

### 动作（Action）
策略输出的数字。T800 是 25 个关节的位置修正量。

### 奖励（Reward）
每一步给策略的分数。强化学习唯一的学习信号。

- 速度跟踪好 → 加分
- 摔倒 → 扣分
- 脚在地上滑 → 扣分

### Episode（回合）
从 reset 到摔倒/超时的一整段过程。T800 现在一个回合 10 秒。

### Termination / Truncation
- Termination：真失败，比如摔倒，回合提前结束
- Truncation：到时间上限，回合正常结束

### Return（回报）
未来奖励的折扣总和。越远的奖励权重越低。

### 折扣因子 γ（gamma）
控制“看多远”。`γ=0.99` 大约关注未来 100 步。

### PPO
Proximal Policy Optimization，一种强化学习算法。它的特点是：每次更新策略时，不让新策略离旧策略太远，避免“学崩”。

### Actor / Critic
- **Actor（演员）**：输出动作
- **Critic（评论家）**：估计“当前状态未来能拿多少分”

Actor 负责做，Critic 负责评。Critic 让训练更稳。

### Value（价值）
Critic 对“当前状态未来回报”的估计。

### Advantage（优势）
“这个动作比平均水平好多少”。优势为正 → 提高这个动作的概率；为负 → 降低。

### GAE
Generalized Advantage Estimation，一种计算优势的方法，平衡偏差和方差。

### Entropy（熵）
衡量策略的“随机程度”。熵高 = 爱探索；熵低 = 很确定。

### Exploration noise（探索噪声）
训练时给动作加随机扰动，让策略尝试新动作。T800 的 `init_noise_std` 就是这个。

### Residual Action（残差动作）
不是直接输出完整动作，而是输出“在参考动作上的小修正”。

```text
最终动作 = 参考动作 + 策略输出 × 缩放
```

类比：**老师给你一份草稿，你只负责改几个字**，比从白纸开始写容易。

### 参考动作（Reference Motion）
一段提前录好的关节轨迹，告诉机器人“正常走路大概长什么样”。策略学的是“跟着参考走 + 保持平衡”。

### 模仿学习（Imitation Learning）
让策略模仿参考动作，而不是完全靠随机探索。

### Sim2Real
把仿真里训练好的策略放到真机上。现实有摩擦、延迟、噪声，通常还要再调。

### Domain Randomization（域随机化）
训练时随机化摩擦、质量、外力等，让策略见过“各种世界”，到真机上更稳。

## 三、工程和训练

### 并行环境（num_envs）
同时跑很多个机器人。8192 个环境 = 8192 个 T800 一起试错，数据收集快。

### steps/s
每秒仿真多少步。越大训练越快。

### Checkpoint
保存的模型文件（`.pt`），可以回放或继续训练。

### TensorBoard
网页曲线面板，看奖励、回合长度、摔倒率等指标。

### 观测归一化
把不同量纲的观测（速度、角度、力矩）缩放到差不多范围，神经网络更好学。

### 奖励归一化
把奖励缩放到稳定范围，避免某些项过大。

### 课程学习（Curriculum）
从简单到难：

```text
先学站 → 再学慢走 → 再学快走 → 再学跑
```

### 局部最优（Local Optimum）
策略找到一个“能拿分但不是你想要”的行为。比如：

- 站着不动，避免摔倒扣分
- 跪着撑到超时
- 双脚蹭着走，不抬脚

**这是人形 RL 最常见的坑。**

## 四、这个项目里的关键名词

### `walk_ref.npz`
从 MuJoCo 的 MNN 走路策略录下来的参考轨迹。里面有 25 个关节角、关节速度、基座状态。

### `RefJointPositionAction`
自定义动作项：

```text
target = ref_joint_pos + action × 0.25
```

### `T800_MIMIC_CFG`
Mimic 任务专用的机器人配置：PD 增益和 MNN 对齐，初始高度 1.01 m。

### `track_joint`
跟踪参考关节角的奖励。误差越小，奖励越接近 1。

### `non_foot_contact`
膝盖/肩膀着地就终止，防止机器人“跪着撑到超时”。

### `feet_air_time_positive_biped`
官方双足步态奖励：只奖励单脚支撑、命令速度 > 0.1 时的步幅。

## 五、一句话记住

```text
观测 = 它能看见什么
动作 = 它能做什么
奖励 = 它想要什么
PPO = 它怎么学
参考动作 = 老师给的草稿
Residual = 它只需要改草稿
```
